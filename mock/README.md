# ForgeDesMondes — maquette

Static mock-up of the proof of concept: plain HTML and JavaScript, no build, no network.

- `index.html` lists the screens; `pages.json` registers every page and micro-frontend.
- `pages/*.html` — one page per screen. Each links `../design/tokens.css`, `../kit/kit.css`, `../style.css` and loads `../mock.js`.
- `components/<Name>.html` — hand-written micro-frontends (no Micro-UI exists under `apps/` yet). Each finds its root with `document.currentScript.closest('[data-component]')`, reads its props from `data-props` and its data from `fixtures/`.
- `mock.js` — renders the design system's kit (`data-kit`) from `data-props`, loads the fragments, and gives them `Mock.fixture`, `Mock.command` (queued → confirmed → applied), `Mock.dialog`, a page bus (`Mock.on` / `Mock.emit`) and `Mock.store`.
- `Mock.store` keeps the battlemap state and what the player view shows in `localStorage`, so the DM view and the player view stay in sync across two tabs and survive a reload. « Réinitialiser la carte » goes back to the fixture.
- `style.css` holds page layout and shared helpers, only through the design system's variables. Never write under `design/` or `kit/`.
- The `design-system` job of `.github/workflows/gates.yml` enforces it too (`node scripts/design-system-gate.mjs`, proved by `scripts/test-design-system-values-gate.sh`). It scans every page, micro-frontend, `style.css`, `mock.js` and fixture under `mock/` — everything but `design/` and `kit/` — and fails the pull request on:
  - a colour literal: a hex, `rgb()`, `hsl()` or any other colour function, or a named colour in a colour property, in a `.css` file, a `<style>` block, an inline `style="…"` or a JS string, `setProperty` and a `var(--color-x, #abc)` fallback included. Only `transparent`, `currentColor`, `none`, `inherit`, `initial` and `unset` pass; there is no exemption, per line or per file. In text a `#abc` is read as a colour after a `:`, a `(` or a `,`, or as a string that is only that; an id selector or an `href="#…"` anchor is not;
  - a `var(--color-*)`, `--font-*`, `--space-*`, `--radius-*`, `--shadow-*` or `--border-width` that `design/tokens.css` does not define (the kit's own `--kit-*` properties are not checked);
  - stylesheet links other than these three, in this order, one `<link rel="stylesheet">` per line: `../design/tokens.css`, `../kit/kit.css`, `../style.css` in a page, `design/tokens.css`, `kit/kit.css`, `style.css` in `index.html`. A fourth `<link`, a missing or repeated one, a swapped order or an `href` that does not resolve fails;
  - a `<link` or an `@import` in a micro-frontend, or an `@import`, a `<link` in JS, or a `url()` of a stylesheet or a font (a `.css` or font file, or a remote address that is not an image) in `style.css`, a `<style>` block or JS. A fragment loads no stylesheet: the page does.
  - Tokens are never copied: a page links the design system's own files, not a `tokens.css` or a `kit.css` of its own (a copy outside `design/` and `kit/` is scanned like any other file).
- A gate enforces it: the `design-system-single-writer` job of `.github/workflows/gates.yml` fails any pull request into `main_agent` or `milestone/**` that adds, changes, deletes or renames a file under `mock/design/` or `mock/kit/`, with one annotation per protected path. The only exempt source is the `design-system` branch of this same repository (a fork's branch of that name is not); the harness carries the design system onto the integration branch when it is published.
- Each fragment names its parts (contract D): `data-writes="<DataCapability>"` on every actuator, `data-reads="<Capability>"` on every part that shows a read, written in the file itself (see `CLAUDE.md`). Kit buttons take `'data-writes'` as an item key.
